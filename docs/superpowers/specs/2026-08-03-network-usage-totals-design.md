# Ace IT Center 网络累计流量设计

日期：2026-08-03

状态：已确认

## 目标

将网络监控设备表调整为以下 8 列：

1. 设备
2. 状态
3. 当前下载
4. 当前上传
5. 今日总下载
6. 今日总上传
7. 本月总下载
8. 本月总上传

当前速度继续用于实时观察；今日和本月字段表示真实传输字节累计，不再使用 24 小时平均值或峰值代替。

## 统计口径

- 所有设备统一按北京时间（UTC+8）的自然日和自然月统计。
- Agent 每 30 秒读取操作系统累计收发字节，并使用相邻读数的正增量更新本地累计值。
- 日累计在北京时间日期变化时清零；月累计在月份变化时清零。
- 当前下载和上传继续使用十进制 `MB/s`。
- 累计流量使用十进制单位并自动格式化为 `B / KB / MB / GB / TB`。
- 新版 Agent 安装或升级前的精确累计流量无法还原，不使用速度样本伪造历史总量。

## Agent 状态

Agent 在既有数据目录中维护一个独立的网络累计状态文件。状态至少包含：

- 格式版本；
- 当前北京时间日期和月份；
- 今日上传、下载字节；
- 本月上传、下载字节；
- 上一次操作系统累计上传、下载字节；
- 是否已经建立计数器基线。

每次有效采样后，Agent 先计算增量，再以临时文件加原子替换的方式保存状态。服务重启和 Agent 自动升级后继续使用该状态，因此不会因进程重启清零。首次运行只建立基线，不把操作系统启动以来的全部流量计入当天。

当操作系统计数器变小、采样时间无效或网卡集合发生导致的计数器回退时，Agent 重新建立基线，本轮增量记为零，避免负数和异常巨量。状态文件损坏或版本不兼容时记录诊断日志并重新初始化，不阻止服务启动和心跳。保存失败时继续当前心跳，记录错误，并在下一轮重试。

为避免 Windows 缺少 IANA 时区数据库造成差异，北京时间使用固定 UTC+8 计算；当前需求不涉及历史夏令时。

## 心跳与服务端存储

心跳在现有实时速度字段之外新增：

- 累计数据是否可用；
- 累计所属北京时间日期；
- 今日上传、下载字节；
- 本月上传、下载字节。

旧 Agent 未发送这些字段时，服务端按“累计数据不可用”处理，不把 JSON 默认值 `0` 误认为真实 `0 B`。日期必须符合 `YYYY-MM-DD` 且字节值不得为负；无效负载返回安全错误，不更新节点或网络样本。

`nodes` 保存每台设备最后一次上报的累计状态，供设备列表一次读取。现有 `network_samples` 继续保存实时上传和下载速度，用于 24 小时、7 天、30 天和 90 天历史曲线；累计功能不替换现有速度历史。

服务端保留现有 `/api/v1/network/summary` 接口以避免破坏兼容，但网络监控表不再轮询它。累计字段随节点列表返回，减少一轮汇总查询。

## 界面行为

表格严格使用目标中的 8 列，下载始终位于上传之前。

- 在线设备显示当前下载和当前上传速度。
- 离线设备的两个当前速度显示 `-`，不显示最后一次速度。
- 离线设备仍显示已经产生的本周期累计流量。
- 若累计日期早于当前北京时间日期，今日累计显示 `0 B`。
- 若累计日期不在当前北京时间月份，本月累计显示 `0 B`。
- 旧 Agent 或尚未完成首次累计采样的设备显示 `-`，与真实 `0 B` 区分。
- 表格在窄屏下横向滚动，列不压缩到内容重叠。
- 行点击和键盘操作继续打开现有网络历史抽屉。
- 页面上方当前下载、上传合计及在线采集设备数量保持不变。
- 原 `NETWORK / 24H` 区段标识改为不限定时间范围的 `NETWORK / TRAFFIC`。

## 发布与升级

累计能力随下一版 Windows Agent 发布，预期版本为 `v0.3.8`。发布内容包括：

- 新 Agent 可执行文件和安装包；
- 服务端接受并保存累计字段；
- 网页下载名称、下载链接和版本显示更新；
- 自动更新清单指向新版本并保留完整性校验。

DSM 上的 backend 和 web 使用 `/volume4/docker/docker/ace-it-center` 中的 Compose 项目更新。现有 Agent 应通过自动更新获取新版本；部署验证必须检查至少一台现有设备自动升级并开始上报累计数据，而不是只验证新安装包。

## 测试与验收

### Agent

- 首次采样只建立基线；
- 连续采样按字节差更新日/月累计；
- 服务重启后从状态文件续算；
- 跨日只重置今日累计；
- 跨月重置今日和本月累计；
- 计数器回退不产生负数或尖峰；
- 损坏、旧版本状态文件安全降级；
- 状态文件原子保存失败可重试；
- 心跳携带累计可用性、周期和四个计数器。

### 服务端

- 旧 Agent 心跳继续成功；
- 数据库迁移可重复执行；
- 有效累计字段被保存并随节点 API 返回；
- 非法日期和负数被拒绝且不产生部分写入；
- 速度历史接口行为保持不变。

### 前端

- 表头文字和顺序完全匹配 8 列目标；
- 在线、离线、旧 Agent 和跨周期数据分别按规则显示；
- 字节单位在边界值正确切换；
- 网络历史行交互保持可用；
- 桌面与窄屏下无文字或控件重叠。

### 线上验收

- backend、web 和 PostgreSQL 容器均为 healthy；
- 公共健康接口返回 HTTP 200；
- 现有 Agent 自动升级至目标版本；
- 连续心跳返回 HTTP 200；
- 当前速度和日/月累计随网络活动增长；
- Agent 服务重启后累计不清零；
- 设备离线后当前速度变为 `-`，累计值保留；
- 网页下载文件名和页面版本一致。
