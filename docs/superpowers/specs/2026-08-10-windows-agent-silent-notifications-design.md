# Ace Agent Windows 静默通知设计

日期：2026-08-10

状态：已确认，待书面审阅

目标版本：Windows Agent `V0.4.10`

## 目标

关闭 Ace Agent 在 Windows 通知区域产生的全部弹窗通知，避免心跳超时、Service 状态变化、更新检查和手动操作结果打断用户。

关闭弹窗不等于隐藏状态或丢弃诊断数据：托盘图标和客户端窗口继续显示当前状态，错误继续写入本地日志，并沿用现有上传机制同步到服务端。

## 通知范围

以下事件不再调用 Windows `ShowInfo` 或 `ShowError`：

- 心跳、网络或 Service 异常；
- Service 恢复和状态变化；
- 配对请求提交结果；
- 手动重启 Worker 的成功或失败结果；
- 手动检查更新的结果；
- 诊断包创建结果；
- 托盘窗口激活失败等本地 UI 错误。

托盘图标本身继续常驻，颜色和工具提示仍按状态变化。用户主动打开客户端窗口时，可以查看 Service 状态、最近心跳和安全错误摘要。

## 客户端反馈

自动状态变化只更新托盘图标、工具提示和客户端窗口，不产生弹窗。

用户在客户端窗口内发起的操作继续提供窗口内反馈：

- 配对请求显示已提交或失败信息；
- Worker 重启显示操作结果；
- 更新检查显示“当前已是最新版本”或发现的版本；
- 诊断包创建显示输出路径；
- 失败信息使用现有安全错误文案，不展示凭据或内部错误。

从托盘右键菜单发起操作时不会额外弹窗。用户需要结果时可打开客户端窗口查看。

## 日志和服务端上传

通知静默不改变 Service 日志链路：

- 心跳和网络错误继续写入 `C:\ProgramData\AceITCenter\logs\agent.log`；
- 自动更新错误继续写入 `C:\ProgramData\AceITCenter\logs\update.log`；
- Agent 在首次成功心跳后上传日志，此后每小时上传一次；
- 服务端继续保存每台设备最新的 Agent 和更新日志快照；
- 日志继续执行现有凭据脱敏、大小限制、轮转和保留策略。

日志上传失败仍只记录到本地日志，不改变设备在线状态，也不产生 Windows 弹窗。

## 实现边界

- 删除状态展示模型产生的自动 `Notification` 内容。
- 移除 Windows 托盘运行时对 `ShowInfo` 和 `ShowError` 的调用。
- 将仍需反馈的手动操作结果写入客户端窗口现有消息区域。
- 保留托盘图标、状态颜色、工具提示、窗口界面和所有现有操作。
- 不新增通知设置、注册表项、配置文件字段或服务端策略。
- 不修改 Backend API、数据库 Schema、Web 版本或 Agent 日志上传协议。

## 测试策略

### 展示模型

- `error` 和 `degraded` 状态保留红色图标及“服务异常”文字，但不产生通知内容；
- `updating` 状态保留蓝色图标及“正在更新”文字，但不产生通知内容；
- Service 不可用时继续清除陈旧状态和操作权限。

### Windows 托盘

- 生产代码不再调用 `NotifyIcon.ShowInfo` 或 `NotifyIcon.ShowError`；
- 配对、重启、更新检查和诊断结果进入窗口内消息区域；
- 自动状态轮询只更新图标、工具提示和窗口字段；
- Windows amd64 交叉编译和安装器构建通过。

### 日志

- 心跳失败仍进入 Service 日志；
- 首次成功心跳后仍上传日志；
- 一小时内不重复上传，上传失败不改变在线状态；
- Credential、Token 和 Authorization 不出现在上传日志中。

## 发布与验收

发布 Windows Agent `V0.4.10`，更新 DSM 稳定版安装包和 `latest.json`。Web 和 Backend 保持当前平台版本，网页展示的 Agent 最新版本随稳定清单变为 `V0.4.10`。

验收至少包括：

1. 手动安装或自动更新到 `V0.4.10`；
2. 制造一次心跳超时，确认托盘状态变红但 Windows 不弹窗；
3. 执行更新检查、Worker 重启和诊断包创建，确认无 Windows 弹窗且窗口内有结果；
4. 确认本地日志记录错误；
5. 确认服务端设备日志快照在首次成功心跳或下一次小时上传后更新；
6. 确认心跳、远程命令和自动静默更新行为不受影响。
